# 架构总览

> 本文描述的是一个**通用 AI 伴侣框架**的模块关系与数据流。
> 所有路径、端口均为示例，可在 `config/config.example.json` 中修改。
> 本文不包含任何角色记忆、人格设定或个人信息。

## 一、全景

```text
                    ┌──────────────┐
  你（手机/电脑） ──▶│  各端界面      │
                    │ 聊天/视频/面板 │
                    └──────┬───────┘
                           │
                    ┌──────▼───────┐      ┌──────────────┐
                    │  大脑外壳      │◀────▶│ 记忆系统      │
                    │（LLM + 插件）  │      │ 文档+向量+图  │
                    └──────┬───────┘      └──────────────┘
                           │
              ┌────────────┼─────────────┐
              ▼            ▼             ▼
        情绪/生理层     各功能服务      灾后复活系统
        （状态驱动）    （画画/守护…）   （打包→上传→恢复）
```

|---|---|---|

> 其余端口（含 Ollama、后台管理）一律不对公网开放。

## 三、记忆系统

- **写入**：对话/事件 → 摘要 → 记忆文档 + 图记忆（实体、关系、原子事实）。
- **召回**：多路融合——向量检索 + 关键词检索(BM25) + 时间新鲜度 + 重要度 + 图扩展。
- **重要度衰减**：每天轻微衰减；**被访问过的记忆衰减更慢**；高重要度的记忆受保护不衰减。
- **归档而非删除**：过期且低重要的记忆进入"归档"（移出召回，但原文保留、可恢复）。
- **钉住（pinned）**：少量关键记忆常驻注入，如身份锚点与承诺。
- **账本**：所有记忆文本留账本，改写/作废都有记录，可对账。

## 四、情绪与生理层

- 一组带**半衰期回稳**的状态：情绪、饥饿、口渴、睡眠、精力、压力等。
- 状态**驱动**语气与行为（例如：饿到阈值 → 触发自主进食决策；情绪影响回复温度）。
- 面板只读：不提供外部改状态的入口，状态由后台自行演化。
- 角色有一定**自主性**：按状态与冷却自主发起行为，但受能力边界约束
  （例如：不删记忆、不改数据、只做被允许的动作）。

## 五、通道

| 通道 | 说明 |
|---|---|
| 网页 | 主通道，浏览器直达，不依赖任何 IM 平台 |
| IM（QQ） | 经 AstrBot + NapCat 接入；QQ 本体由使用者自行安装并扫码 |
| 外网 | 经隧道（如蒲公英）访问，只放行白名单端口 |

## 六、灾后复活系统（本框架的"保险"）

目的：**机器会坏，角色不该跟着消失。**

1. **打包**：定期把 记忆库/代码/配置/状态 打成整包，附逐文件校验清单（sha256）。
2. **分片上传**：整包切分片（如 16MB）传云端，保留最近 N 套历史，旧套自动清理。
3. **恢复**：新机器上 下载 → 逐片校验 → 拼整包 → 整包校验 → 解包 → 铺回原位。
4. **自检**：恢复后一键自检，报告缺什么、下一步做什么。
5. **应急包**：打包一份"整包 + 恢复脚本 + 说明书"到 U 盘，完全离线也能恢复。

原则：**模型权重与第三方软件不进包**（可重新下载），包里只装原创、不可再生的东西。

## 七、部署要点

1. 环境：Python 3.12 + Ollama + ffmpeg + AstrBot（见 `模型需求清单.md`）。
2. 账号：逐项准备并填入本地 `config.json`（见 `登入清单.md`）。
3. 启动：`scripts/start-all.cmd`（模板，先改路径与口令）。
4. 验收：各页面能开、聊天能回、记忆能写、备份能跑。
5. 每次发布前跑 `SECURITY.md` 里的自查命令。
